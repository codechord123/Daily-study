# 문제 만들기·관리 규칙

아침 미션에 나오는 모든 문제(문항 은행 + 자동 생성 문제)는 이 규칙을 따른다.
**[자동]** 표시가 있는 규칙은 `npm run check:questions` 가 검사하고, 하나라도 어기면 실패한다. 나머지는 사람이 그림 검수 페이지를 보며 확인한다.

---

## 1. 정확성

| 번호 | 규칙 |
|---|---|
| R1 [자동] | 형식이 맞아야 한다: 문제 종류(고르기·O/X·수·쓰기), 문제 글, 보기 2개 이상, 정답 번호가 보기 안에 있음, O/X는 참·거짓, 수 문제는 수 |
| R2 [자동] | 정답은 하나뿐이다. 보기끼리 겹치지 않는다. 수 정답은 음수가 아니고 소수 둘째 자리 안에서 깔끔하다 |
| R2-1 | 정답이 아닌 보기가 '어떻게 보면 맞는' 일이 없어야 한다. 예: 점대칭이 아닌 보기로 넣은 연꼴이 마름모처럼 보이면 안 된다 |
| R3 [자동] | 문항 은행 문제는 풀이(explain)가 있다. 풀이의 수와 정답이 같아야 한다 |
| R4 [자동] | 힌트가 정답을 알려 주면 안 된다. 힌트는 '힌트 보기'를 눌러야 보이고, 생각할 방향만 알려 준다 |

## 2. 그림

| 번호 | 규칙 |
|---|---|
| R10 [자동] | '이 그림', '이 도형', '분홍 점선' 처럼 그림을 가리키는 문제에는 반드시 그림이 있다 |
| R10-1 | 도형의 길이·각·대응을 묻는 문제는 글만으로 내지 않고 그림을 함께 낸다 |
| R11 [자동] | 그림 좌표가 깨지지 않는다 (NaN 등) |
| R12 [자동] | 문제와 보기에 나오는 이름(변 ㄱㄴ, 선분 ㄱㄷ, 각 ㄱㄴㄷ, 점 ㅇ …)은 그림에 모두 적혀 있다 |
| R13 [자동] | **길이는 어느 변(선분)의 길이인지 양 끝까지 표시한다.** 변과 나란한 파란 치수선(양 끝 눈금)을 긋고 가운데에 길이를 쓴다. 글자만 변 옆에 두지 않는다. 선분 ㅇㄱ의 길이면 ㅇ에서 ㄱ까지만 표시한다 |
| R13-1 | 문제가 묻는 변은 그림에서도 그 변에 `?cm` 로, 묻는 각은 `?` 로 표시한다 |
| R14 [자동] | 각은 꼭짓점에 빨간 호를 그리고 각도를 쓴다. 호는 그 각이 실제로 있는 꼭짓점에 둔다 |
| R15 | 그림은 실제 비율대로 그린다. 3cm가 4cm보다 길어 보이거나, 60°가 90°처럼 보이면 안 된다 |
| R16 | 글자끼리, 글자와 선이 겹치지 않는다. 꼭짓점 이름은 그림 밖으로 잘리지 않는다 |
| R17 | 대칭축은 분홍 점선, 대칭의 중심은 분홍 점과 ㅇ으로 표시한다 |

## 3. 난이도와 문장

| 번호 | 규칙 |
|---|---|
| R20 [자동] | 더 내지 않기로 한 옛 문제는 나오지 않는다 (`src/data/missions/retired.js`). 다시 보기·남은 오답에서도 빠진다 |
| R21 | ×2, ÷2, 같은 수 옮겨 쓰기처럼 한 단계로 끝나는 문제는 내지 않는다. 대응 찾기 + 계산처럼 최소 두 단계이거나, 개념을 판단하게 한다 |
| R22 | 5학년이 아는 낱말로 쓴다. 상황(작게)과 묻는 말(크게)을 나눈다. 수 문제의 단위는 문장 끝 괄호에 쓴다: `(cm)`, `(°)` |
| R23 | '아닌 것', '틀린 것'을 묻는 문제는 그 말이 문장에 분명히 드러나게 쓴다 |

## 4. 범위

| 번호 | 규칙 |
|---|---|
| R30 [자동] | 모든 문제는 정해진 단원 번호를 가진다 |
| R31 [자동·주의] | 문항 은행 문제는 성취기준(std)을 단다 |
| R32 [자동] | 같은 문제가 은행에 두 번 들어가지 않는다 |
| R33 | 선생님이 고른 단원에서만 낸다. 과학은 '자원과 에너지' 단원만 |
| R34 | 영어 듣기는 미리 만든 소리 파일로 튼다 (새 영어 문장을 넣으면 `scripts/en-audio` 로 소리 파일도 만든다) |

## 관리 절차

1. **새 단원 문제**는 바로 앱에 넣지 않는다. 검수용 파일로 만들어 선생님께 보내고, 선생님이 검수하고 요청한 뒤에 은행에 넣는다.
2. **문제를 넣거나 고치거나 생성기를 바꾼 뒤**에는
   - `npm run check:questions` 를 실행해 오류 0을 확인한다.
   - `npm run check:questions -- --sheet` 로 `review/문제그림.html` 을 만들어 그림을 눈으로 확인한다 (R2-1, R13-1, R15, R16). 규칙에 걸린 문제는 빨간 테두리로 보인다.
3. **학생이 '문제가 이상해요'를 누르면** 선생님 화면 › 학습 분석 › '학생들이 알려 준 문제'에 모인다. 크게 띄워 확인하고
   - 잘못된 문제면 '출제에서 빼기'를 누른 뒤 고칠 문제로 알려 준다.
   - 고친 문제는 검사기를 통과해야 다시 나온다.
4. **생성 문제 틀을 없애거나 바꿀 때**는 옛 문장 모양을 `retired.js` 에 적는다. 그래야 학생들의 다시 보기·남은 오답에 남은 옛 문제가 빠진다.
5. 이 규칙을 바꾸면 검사기(`scripts/check-questions.mjs`)도 함께 고친다.
