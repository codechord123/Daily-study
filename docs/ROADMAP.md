## 배포 계획: 웹 · Android · iOS (2026-10-18 결정)
같은 코드 하나로 세 곳에 낸다.

| 대상 | 방법 |
|---|---|
| 웹 | Vercel (`npm run build` → `dist/`) |
| Android (Play 스토어) | Capacitor로 `dist/`를 감싼 앱 |
| iOS (App Store) | Capacitor, Mac + Xcode 필요 |

지금부터 지켜 둘 것 (나중에 고치기 어려운 것들)
- 빌드는 상대 경로(`base: './'`) — 이미 적용
- 소리는 첫 터치 이후 재생 — 앱 웹뷰도 같은 자동재생 제한이 있음, 이미 적용
- 화면 노치·하단 바: `env(safe-area-inset-*)` 사용 중 — 이미 적용
- 로그인: Google 로그인은 앱 안에서 웹 팝업 방식이 막히므로 Capacitor용 Firebase Auth 플러그인 필요 (Firebase 연결 때 함께)
- 어린이 대상 앱 심사: 앱스토어 '키즈' 카테고리 / Play '가족' 정책 → 외부 광고·분석 SDK 금지, 개인정보처리방침 URL 필수, 학생 실명 수집 최소화
- iOS는 웹을 감싸기만 한 앱을 거절하기도 함(가이드라인 4.2) → 3D·오프라인 미션·알림 등 앱다운 기능이 있으면 유리. 아침 미션 알림(로컬 푸시) 추가를 권장
- 오프라인: 앱 안에 파일이 들어가므로 미션은 인터넷 없이도 풀리게, 결과는 연결되면 전송

## 아이디어: 시험은 "한 별에 모두 모여서" 디지털로 보기 (2026-10-18 제안)
반 전체가 선생님 별(또는 '시험의 별')로 날아와 모인 상태에서, 같은 시각에 시험을 시작하는 방식.

왜 좋은가
- 이미 있는 실시간 함께 있기(presence)·미션 엔진·문제 카드 UI를 그대로 재사용 → 추가 비용이 작다
- "모두 모였는지"가 별 위 캐릭터로 한눈에 보임 → 출석/준비 확인이 자연스러움
- 아침 미션(연습)과 시험(평가)이 같은 화면 문법이라 아이들이 낯설어하지 않음

설계 메모 (구현 전 결정 필요)
- 교사 화면에서 [시험 열기] → 학생들은 "시험의 별"로 이동 → 교사가 [시작] 누르면 동시에 시작
- 시험 중에는 이모트·여행·꾸미기 잠금, 친구 캐릭터는 보이되 정답/진행 상황은 비공개
- 미션과 달리 정답 연출(별 조각·반짝이)은 끄고 제출 후 일괄 채점 (평가 공정성)
- 문항 순서·보기 순서 학생별로 섞기 (옆 기기 보기 방지)
- 제한 시간, 제출 후 수정 불가, 네트워크 끊김 시 답안 임시 저장 후 재전송
- 결과: 교사에게 문항별 정답률·학생별 점수, 학생에게는 교사가 공개를 누른 뒤에만
- 필수 선행 조건: Firebase(서버 시각 동기화, 답안 서버 저장, 채점은 서버 함수)
